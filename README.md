# SpeakOut — [@SpeakOutEducation_bot](https://t.me/SpeakOutEducation_bot)

Разговорный английский в Telegram. Ты записываешь голосовое — ИИ-собеседник отвечает голосом, а в конце разговора даёт разбор.

## Чем отличается

Мы разобрали Speak, ELSA, Praktika, Loora, TalkPal и Gliglish. У всех, кто делает ИИ-собеседника, повторяется одна и та же жалоба: **«разговоры зацикливаются и остаются поверхностными»**. У Speak отдельно — «нет системы долгосрочного удержания».

Причина у всех одна: **ИИ не помнит**. Каждый разговор начинается с нуля. Вчера ты двенадцать раз ошибся в артиклях — сегодня собеседник об этом не знает.

SpeakOut построен вокруг памяти:

| Что | Как это сделано |
|---|---|
| **Память между сессиями** | `users.memory_summary` — сжатая заметка, которую модель переписывает после каждого разговора и читает перед следующим |
| **Журнал ошибок → практика** | Каждая правка размечается категорией; повторяющиеся категории подкладываются в следующие разговоры |
| **Правки не перебивают** | Во время разговора — ничего. Разбор в конце, максимум 3 ошибки, отобранные по тяжести и готовности уровня |
| **Скорость речи по уровню** | A1 звучит на 0.82×, C2 на 1.1×. Снимает жалобу «ИИ говорит слишком быстро» |
| **Заточка под русскоязычных** | Артикли, аспект, `I am agree`, оглушение конечных согласных, `ship/sheep` |
| **Слова из реальных разговоров** | Карточки создаются из того, что ты действительно сказал, а не из списка |

## Быстрый старт

```bash
git clone <repo> && cd Telegramm_bot_English-speak
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env    # заполни ключи
alembic upgrade head    # создать схему
python -m scripts.seed  # загрузить темы разговоров
python -m bot           # запустить
```

Нужен **ffmpeg** в системе — без него не будет голоса:

```bash
sudo apt install ffmpeg     # или: brew install ffmpeg
```

### Supabase

В `.env` бери строку из Project Settings → Database → Connection string, и **обязательно session-mode пулер, порт 5432**, а не transaction mode (6543). В transaction mode asyncpg ловит плавающие `prepared statement ... does not exist`, которые невозможно отладить. Схему меняем только через Alembic — не через SQL-редактор в дашборде, иначе история миграций разойдётся с реальностью.

На free-тарифе проект засыпает после недели простоя, и бот начнёт падать на коннекте. Для боевого запуска нужен платный.

### Голоса

`voice_id` в `bot/personas.py` — дефолтные голоса ElevenLabs. Проверь, что они есть на твоём аккаунте:

```bash
python -m scripts.list_voices
```

```
├── __main__.py          композиция: config → bot → dispatcher → polling
├── personas.py          5 персонажей: голос, акцент, характер, скорость
├── texts.py             все русские тексты интерфейса
├── data/topics.py       16 тем разговора с целью для каждой
├── db/                  модели, репозитории, движок
├── middlewares/         сессия БД, загрузка юзера, троттлинг
├── handlers/            start · conversation · review · progress · settings
└── services/
    ├── llm.py           два вызова Claude: собеседник и оценщик
    ├── stt.py           Whisper с таймкодами по словам
    ├── tts.py           ElevenLabs / OpenAI + ffmpeg + скорость
    ├── fluency.py       беглость речи из таймкодов — бесплатно, без модели
    ├── feedback.py      отбор правок: что показать, а что промолчать
    ├── srs.py           SM-2
    ├── conversation.py  оркестрация хода
    └── speak.py         отправка голосом + кэш file_id
```

### Как устроен один ход

```
голосовое
  → Whisper (таймкоды по словам)
  → беглость из таймкодов        ┐ считается локально, ничего не стоит
  → Claude: ответ собеседника    ├ параллельно (asyncio.gather)
  → Claude: разбор ошибок        ┘ — ждём медленный, а не сумму
  → запись хода + ошибок + новых слов (одна транзакция)
  → TTS в голосе персонажа → кэш по хешу → отправка
```

Два вызова модели разделены намеренно. У собеседника и у проверяющего противоположные инстинкты: первый хочет продолжать разговор, второй — остановиться и исправить. Один промпт на обе роли даёт бота, который либо перебивает постоянно, либо не исправляет никогда.

Отбор правок живёт в `feedback.py`, то есть **в коде, а не в промпте** — значит, педагогику можно тестировать и менять, не перебирая формулировки.

## Экономика

Порядок цифр на одну 10-минутную голосовую сессию (~12 ходов):

| Статья | Стоимость |
|---|---|
| Whisper (10 мин входа) | ~$0.06 |
| Claude Opus 5, 24 вызова | ~$0.15–0.30 |
| ElevenLabs TTS (~3 000 знаков) | ~$0.30–0.60 |
| **Итого** | **~$0.50–0.95** |

Рычаги, если станет дорого — в порядке отдачи:

1. **`TTS_PROVIDER=openai`** — падает в 6–12 раз (с ~$0.45 до ~$0.05), качество голоса заметно ниже. Самый крупный рычаг.
2. **`ASSESSOR_MODEL=claude-sonnet-5`** — разбор ошибок дешевле в 2.5 раза, задача структурная и терпит.
3. **`FREE_DAILY_TURNS=20`** — жёсткий потолок на пользователя в день.
4. Кэш `audio_cache` уже работает — повторные фразы бесплатны.

Всё расходование пишется в `usage_days` с первого дня, поэтому реальную цену пользователя видно сразу, а не в счёте в конце месяца.

По умолчанию стоит `claude-opus-5` на обе роли — это осознанный выбор в пользу качества; понижать до Sonnet стоит по факту нагрузки, а не заранее.

## Ограничения, о которых честно

- Голосовые асинхронные: ответ приходит за 2–4 секунды, это не живой звонок.
- Bot API не даёт скачать файл больше 20 МБ — отсюда лимит в 120 секунд на сообщение.
- FSM в памяти, если не задан `REDIS_URL`. Состояние разговора лежит в Postgres, так что перезапуск теряет только незаконченный онбординг — но перед запуском второй реплики Redis обязателен.
- Whisper иногда «поправляет» грамматику говорящего. Мы гасим это промптом, но не полностью — не показывай пользователю правку, если не уверен в транскрипте.
